# 合作入口的營運規範

Vessel 的連線可以分成入口與節點兩段：使用者先連到入口，入口把封包原封不動轉送到節點，再從節點連上網路。兩段都由 anoni.net 營運時，社群在技術上可以同時知道使用者的 IP 與連線的目的地。入口交給另一個團體營運，任何一方都只握有其中一半，這份規範寫明營運入口的團體要遵守的事，以及 anoni.net 對入口營運者的承諾。

規範適用於每一個合作入口，內容改版時會通知所有營運者，並保留舊版的紀錄。

## 各方看得到的資訊

| | 使用者的 IP | 連線的目的地與內容 | 流量的時間與大小 |
|---|---|---|---|
| 入口營運者 | 看得到 | 看不到，通道沒有在入口解開 | 看得到 |
| anoni.net（節點） | 看不到，節點只看到入口的位址 | 目的地看得到，內容如果是 HTTPS 則看不到 | 看得到 |
| 入口主機的業者、入口所在地的網路業者 | 看得到 | 看不到 | 看得到 |

## 入口營運者的承諾

1. 只轉送封包，不解開通道，也不修改封包的內容。使用 `vessel-relay` 或效果相同的設定，並公開使用的版本與設定（節點的 IP 除外）
2. 不記錄使用者的 IP、連線的時間與每筆連線的流量。主機、防火牆與雲端平台的連線紀錄（例如 VPC flow log）要關閉。為了維運只保留總計，例如每天經過入口的總流量
3. 不把使用者的 IP 或任何連線資料交給 anoni.net，也不交給其他人。收到政府或法院的調閱要求時，依所在地的法律處理，並在法律允許的範圍內公開這類要求的次數
4. 節點的 IP 只用在轉送的設定裡，不公開，也不轉交給第三方
5. 主機只開放轉送與管理需要的埠，管理登入使用金鑰，系統的安全更新在一週內套用
6. 計畫中的維護至少提前一天通知 anoni.net。決定退出時至少提前 30 天通知，讓使用者有時間改用其他路線

## anoni.net 的承諾

1. 使用者建立裝置時，看得到每條路線的入口由哪個團體營運，入口清單與營運者公開在服務的頁面上
2. 不要求入口營運者提供使用者的資料，也不在入口主機上安裝任何程式
3. 節點換主機或換 IP 時，提前通知入口營運者更新轉送的目標
4. 連往其他網站的流量從節點出去，用的是節點的 IP，所以濫用通報會寄到 anoni.net，由 anoni.net 依服務的使用條款處理。入口的 IP 只和使用者與節點往來，不會出現在其他網站的紀錄裡。入口營運者收到相關的通報時轉給 anoni.net 即可，不需要查出是哪個使用者
5. 入口的費用、頻寬上限與分攤方式，在合作開始前以書面約定

## 無法防護的範圍

使用者要知道下列限制，服務的常見問題與隱私權政策也會寫明：

- 入口營運者與 anoni.net 串通，或兩邊同時被監看時，可以從封包的時間與大小比對出使用者與連線的目的地
- 入口營運者知道哪些 IP 在使用 Vessel
- anoni.net 無法從技術上確認入口真的沒有記錄，只能依靠公開的設定、這份規範與營運者的信用
- 入口所在地的法律可能要求業者保存連線紀錄，選擇合作對象時會考慮這一點，並把入口的所在地告訴使用者

## 查核與退出

- 營運者同意公開 `vessel-relay` 的版本與設定（節點的 IP 除外），anoni.net 可以請營運者提供 `vessel-relay status` 的輸出與防火牆的設定，確認入口只做轉送
- 任何一方發現對方違反規範時，以書面提出，雙方先討論改善。無法改善時，anoni.net 停止提供那條路線，並在服務狀態頁公告
- 合作結束時，入口營運者執行 `vessel-relay remove` 並刪除設定檔，anoni.net 讓透過那條路線的使用者改用其他路線
