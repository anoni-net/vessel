# 連線請求的檢查

確認節點看得出連不上的裝置。worker 每次讀用量時，把「上一次讀取之後收到這台裝置的封包，但最近一次建立連線的時間太舊，收到的不可能是資料」的裝置算成連不上（`api/app/jobs.py` 的 `failing`）。這個判斷靠的是 AmneziaWG 的兩個行為：網路擋掉節點的回應時，節點仍然把裝置送來的連線請求算進收到的位元組，最近一次建立連線的時間則維持原樣。升級 AmneziaWG 之後執行一次，確認行為沒有改變。整個測試在本機的容器裡完成，不連到任何節點，也不會建立正式的 peer。

```bash
tools/handshake-check/run.sh      # 約 5 分半，每一項印出 ok 或 FAIL，有 FAIL 時結束碼是 1
```

## 做法

腳本用 `node/Dockerfile` 固定的 AmneziaWG 版本起一個伺服器與三個用戶端，參數取自 `node/setup.sh` 與 `node/awgctl`，跟節點實際在用的相同。用戶端每秒 ping 伺服器一次，伺服器那一端讀 `awg show awg0 dump`。

| 用戶端 | 用 iptables 擋掉的封包 | 預期在伺服器看到的 |
|---|---|---|
| c1 | 先正常連上，60 秒之後擋掉伺服器的回應 | 最近一次建立連線的時間越來越舊，收到的位元組仍然增加 |
| c2 | 一開始就擋掉伺服器的回應 | 從沒建立連線，收到的位元組持續增加 |
| c3 | 一開始就擋掉用戶端送出的封包 | 什麼都沒有 |

2026-11-11 用 `amneziawg-go:3.1.20260828` 的結果符合預期。c2 每秒大約多收到 50 bytes，也就是每 5 秒一次的連線請求。c1 被擋之後的前 3 分鐘還收得到舊連線的資料，之後只剩連線請求，增加的速度跟 c2 相同。c3 這種情況節點完全看不出來，跟使用者沒有開啟連線一樣。
